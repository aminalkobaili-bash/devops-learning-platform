## Топология

| Узел | Роль | enp0s3 | enp0s8 |
|---|---|---|---|
| **r1** | роутер | `10.10.0.1/18` | `10.100.0.11/16` |
| **r2** | роутер | `10.100.0.12/16` | `10.20.0.1/26` |
| **ws11** | хост | `10.10.0.2/18`, gw `10.10.0.1` | — |
| **ws21** | хост | `10.20.0.10/26`, gw `10.20.0.1` | — |
| **ws22** | хост | `10.20.0.20/26`, gw `10.20.0.1` | — |

```
ws11 ── 10.10.0.0/18 ── r1 ── 10.100.0.0/16 ── r2 ── 10.20.0.0/26 ── ws21, ws22
```

## Что нужно, чтобы пакет дошёл ws11 → ws21

| Где | Что | Зачем |
|---|---|---|
| ws11 | `gateway4: 10.10.0.1` | всё чужое — на r1 |
| r1 | `ip_forward = 1` | пересылать чужие пакеты |
| r1 | `10.20.0.0/26 via 10.100.0.12` | сеть ws21 — за r2 |
| r2 | `ip_forward = 1` | |
| r2 | `10.10.0.0/18 via 10.100.0.11` | **обратный путь** для ответа |
| ws21 | `gateway4: 10.20.0.1` | ответ — на r2 |

Сети `10.10.0.0/18` и `10.20.0.0/26` подключены к роутерам напрямую (connected), поэтому r1 знает про свою и не знает про чужую — для неё статический маршрут.

## ip_forward

По умолчанию Linux **отбрасывает** пакеты, адресованные не ему. Роутером он становится после включения пересылки:

```bash
sudo sysctl -w net.ipv4.ip_forward=1        # сразу, до перезагрузки
echo 'net.ipv4.ip_forward=1' | sudo tee -a /etc/sysctl.conf
sudo sysctl -p                               # перечитать /etc/sysctl.conf
sysctl net.ipv4.ip_forward                   # проверка: = 1
```

Аналог через файл ядра: `cat /proc/sys/net/ipv4/ip_forward`.

## Longest prefix match

Если адресу подходят несколько маршрутов, выигрывает самый **длинный префикс** — самый точный.

На ws11 есть два маршрута, под которые попадает `10.10.0.5`:

| Маршрут | Префикс |
|---|---|
| `0.0.0.0/0 via 10.10.0.1` (default) | `/0` — подходит любой адрес |
| `10.10.0.0/18 dev enp0s3` (connected) | `/18` |

Выбирается `/18`: пакет уходит напрямую, а не через r1. Default (`/0`) срабатывает, только если не подошло ничего точнее.

```bash
ip r list 10.10.0.0/18     # connected-маршрут
ip r list 0.0.0.0/0        # default via 10.10.0.1
ip route get 10.10.0.5     # какой выбран на самом деле
```

## TTL

Каждый роутер уменьшает TTL пакета на 1. Дошло до 0 — роутер отбрасывает пакет и отправляет отправителю `ICMP Time Exceeded`. Это защита от бесконечных петель маршрутизации.

В `ping` видно, сколько роутеров по пути: Linux отправляет с TTL 64, пришёл ответ с `ttl=63` — один хоп.

## traceroute

```bash
traceroute 10.20.0.10      # с ws11
#  1  10.10.0.1    (r1)
#  2  10.100.0.12  (r2)
#  3  10.20.0.10   (ws21)
```

Как работает:

1. Шлёт UDP-пакеты на высокие порты (33434+) с TTL = 1, 2, 3…
2. Каждый роутер, у которого TTL обнулился, отвечает `ICMP Time Exceeded` — так видно его адрес.
3. Цель отвечает `ICMP port unreachable` (на этом порту никто не слушает) — трассировка закончена.

В проекте `tcpdump -tnv` на r1 показал UDP-пробы на порты 33442–33445 с растущим TTL и ответы `ICMP udp port unreachable` от цели.

## tcpdump

```bash
sudo tcpdump -n -i enp0s3 icmp
```

| Флаг | Значение |
|---|---|
| `-i enp0s3` | интерфейс |
| `-n` | не разрешать адреса и порты в имена |
| `-t` | не печатать время |
| `-v` | подробнее: TTL, длина, флаги |
| `-e` | показать MAC-адреса |
| `icmp`, `port 67`, `host 10.20.0.10` | фильтр: что захватывать |
| `-w file.pcap` | записать в файл для Wireshark |

## ICMP Destination Net Unreachable

```bash
ping 10.30.0.111     # с ws11
# From 10.10.0.1 icmp_seq=1 Destination Net Unreachable
```

ws11 отправил пакет на шлюз r1 (default). У r1 нет маршрута к `10.30.0.0` и нет своего default — r1 отвечает ICMP-ошибкой. Ответ пришёл **от r1** (`From 10.10.0.1`): по адресу отправителя видно, на каком роутере путь оборвался.

| Сообщение | Значение |
|---|---|
| `Destination Net Unreachable` | у роутера нет маршрута в сеть |
| `Destination Host Unreachable` | сеть есть, но хост не отвечает на ARP |
| `Destination Port Unreachable` | хост есть, порт закрыт (UDP) |
| `Time to live exceeded` | TTL обнулился — петля или traceroute |
