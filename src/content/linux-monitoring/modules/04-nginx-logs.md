## Формат combined

Стандартный формат access-лога nginx и Apache. Строка из сгенерированного лога проекта:

```
111.161.196.237 - - [17/Mar/2026:00:00:11 +0000] "POST /products HTTP/1.1" 200 1024 "-" "Library"
```

| Поле awk | Значение | Пример |
|---|---|---|
| `$1` | IP клиента | `111.161.196.237` |
| `$2` | identd (почти всегда `-`) | `-` |
| `$3` | пользователь при HTTP-аутентификации | `-` |
| `$4` `$5` | время и часовой пояс | `[17/Mar/2026:00:00:11` `+0000]` |
| `$6` | метод (с кавычкой) | `"POST` |
| `$7` | URL | `/products` |
| `$8` | протокол | `HTTP/1.1"` |
| `$9` | **код ответа** | `200` |
| `$10` | размер ответа в байтах | `1024` |
| `$11` | Referer | `"-"` |
| `$12…` | User-Agent | `"Library"` |

awk делит строку по пробелам, поэтому номер поля зависит от того, сколько пробелов внутри кавычек. User-Agent `"Google Chrome"` займёт `$12` и `$13`.

## Коды ответа

| Класс | Значение | Из генератора |
|---|---|---|
| 2xx | успех | 200 OK, 201 Created |
| 3xx | перенаправление | — |
| 4xx | **ошибка клиента** | 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found |
| 5xx | **ошибка сервера** | 500 Internal Server Error, 501 Not Implemented, 502 Bad Gateway, 503 Service Unavailable |

> 502 Bad Gateway — nginx как reverse proxy не получил корректный ответ от бэкенда (упал, не запущен). 504 Gateway Timeout — бэкенд не ответил вовремя.

## Генератор логов

```bash
METHODS=(GET POST PUT PATCH DELETE)
CODES=(200 201 400 401 403 404 500 501 502 503)

METHOD=${METHODS[$RANDOM % ${#METHODS[@]}]}
IP="$((RANDOM%255)).$((RANDOM%255)).$((RANDOM%255)).$((RANDOM%255))"
DATE=$(date -d "-$day day" +"%d/%b/%Y")
```

| Конструкция | Значение |
|---|---|
| `ARR=(a b c)` | массив |
| `${#ARR[@]}` | длина массива |
| `${ARR[i]}` | элемент |
| `$RANDOM` | случайное число 0–32767 |
| `date -d "-3 day"` | дата 3 дня назад (GNU date) |
| `$((RANDOM % 900 + 100))` | случайное число 100–999 |

5 файлов по 100–1000 строк, всего в проекте — 2838 строк.

> Генератор хранит время в переменной `SECONDS`. В bash это **служебная** переменная: она сама увеличивается каждую секунду с момента присваивания. Генерация идёт быстрее секунды, так что на результат это почти не влияет, но для своих данных лучше брать обычное имя, например `ts`.

> `$RANDOM%255` даёт 0–254: адресов с `255` и, например, `0.x.x.x` в реальном логе не будет. Для учебных данных это не важно.

## Разбор через awk

```bash
LOGS=access_log_*.log

awk '{print $0}' $LOGS | sort -k9 -n                    # 1: все записи по коду ответа
awk '{print $1}' $LOGS | sort | uniq                    # 2: уникальные IP
awk '$9 >= 400 && $9 < 600' $LOGS                       # 3: запросы с ошибками
awk '$9 >= 400 && $9 < 600 {print $1}' $LOGS | sort | uniq   # 4: уникальные IP с ошибками
```

| Конструкция | Значение |
|---|---|
| `awk 'условие {действие}'` | для строк, где условие истинно |
| `awk 'условие'` | без действия — напечатать строку |
| `sort -k9 -n` | сортировать по 9-му полю как числу |
| `sort \| uniq` | `uniq` убирает только **соседние** дубликаты — поэтому сначала `sort` |

В режиме 1 `awk '{print $0}'` лишний: `sort -k9 -n $LOGS` делает то же самое.

### Частые аналитические запросы

```bash
awk '{print $9}' $LOGS | sort | uniq -c | sort -rn             # сколько каких кодов
awk '{print $1}' $LOGS | sort | uniq -c | sort -rn | head      # топ IP по числу запросов
awk '{print $7}' $LOGS | sort | uniq -c | sort -rn | head      # топ URL
awk '$9 >= 500 {c++} END {print c+0}' $LOGS                    # число 5xx
```

`uniq -c` добавляет перед строкой количество повторов, `sort -rn` сортирует по нему по убыванию.

На образце из репозитория (20 строк): 16 запросов с кодами 4xx/5xx, чаще всего — 403 (5 раз).

## GoAccess

Интерактивный и HTML-отчёт по access-логу: посетители, URL, коды, User-Agent, время.

```bash
cat access_log_*.log > all_logs.log
goaccess all_logs.log --log-format=COMBINED -o report.html
```

`--log-format=COMBINED` — формат строк. Отчёт проекта — `samples/goaccess-report.html` по 2838 строкам.

## Недочёт из README

Анализатор читает `../04/access_log_*.log` — путь от структуры учебного репозитория, относительно **текущей** папки. Нечисловой аргумент обрабатывается непредсказуемо: в `[[ $MODE -lt 1 ]]` значение вычисляется арифметически. `abc` bash считает именем пустой переменной (= 0) — и выводит «Parameter must be 1-4» по случайности. А `1a` даёт ошибку bash `value too great for base`. Надёжно — проверять регуляркой: `[[ $MODE =~ ^[1-4]$ ]]`.
