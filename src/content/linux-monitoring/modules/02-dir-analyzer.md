## Что делает dir-analyzer

```bash
./main.sh /var/log/
```

Выводит по каталогу: число папок и файлов, количество файлов по типам, топ папок и файлов по размеру, топ исполняемых файлов с MD5-хешем и время работы скрипта.

## find — главный инструмент

```bash
find "$DIR" -type f                          # все файлы рекурсивно
find "$DIR" -type d                          # все каталоги
find "$DIR" -type l                          # символические ссылки
find "$DIR" -type f -name "*.conf"           # по маске имени
find "$DIR" -type f -executable              # исполняемые
find "$DIR" -type f \( -name "*.zip" -o -name "*.gz" \)   # ИЛИ: скобки экранируются
```

| Выражение | Значение |
|---|---|
| `-type f / d / l` | файл / каталог / ссылка |
| `-name "*.log"` | маска имени (кавычки обязательны, иначе маску раскроет shell) |
| `-o` | ИЛИ (по умолчанию условия объединяются через И) |
| `-size +100M` | больше 100 МБ |
| `-mtime -1` | изменён меньше суток назад |
| `-exec cmd {} \;` | выполнить команду для каждого файла |
| `-exec cmd {} +` | выполнить команду **один раз** для пачки файлов — намного быстрее |

Подсчёт — через `| wc -l`.

## Подсчёт каталогов

В скрипте:

```bash
ls -lR "$DIR" | grep -c "^d"
```

Работает, но парсит вывод `ls` — он предназначен для человека. Надёжнее:

```bash
find "$DIR" -mindepth 1 -type d | wc -l
```

`-mindepth 1` исключает сам `$DIR`.

## Тип файла по содержимому: file

```bash
file /var/log/syslog         # /var/log/syslog: ASCII text
file /usr/bin/ls             # ELF 64-bit LSB pie executable …
```

`file` смотрит на сигнатуру внутри файла, а не на расширение. В скрипте текстовые файлы считаются так:

```bash
find "$DIR" -type f -exec file {} \; | grep -i text | wc -l
```

`-exec … \;` запускает `file` отдельно для каждого файла. Для тысяч файлов быстрее `-exec file {} +`.

## Топ по размеру: du + sort

```bash
du -h --max-depth=1 "$DIR" | sort -rh | head -n 5           # каталоги
find "$DIR" -type f -exec du -h {} + | sort -rh | head -10   # файлы
```

| Часть | Зачем |
|---|---|
| `du -h` | размер в K/M/G |
| `sort -h` | сортировка «человеческих» размеров: `900K < 1.2M < 3G` |
| `-r` | по убыванию |
| `head -n 5` | первые 5 |

> `du --max-depth=1 /var/log/` выводит и подкаталоги, и **сам** `/var/log/` — он всегда самый большой и попадает в топ первым. Это недочёт 4 из README. Исправление: `du -h --max-depth=1 "$DIR" | sort -rh | tail -n +2 | head -n 5` или `du -sh "$DIR"*/`.

## MD5 исполняемых файлов

```bash
md5sum /usr/bin/ls     # 0123…abcd  /usr/bin/ls
```

Хеш — отпечаток содержимого. Сравнение с эталоном показывает, что бинарник не подменили. MD5 устарел для криптографии (возможны коллизии), для проверки целостности против злоумышленника берут `sha256sum`.

## while read и пробелы в путях

```bash
find "$DIR" -type f -exec du -h {} + | sort -rh | head -10 |
while read size filepath; do
    echo "$counter - $filepath, $size"
    ((counter++))
done
```

- `read size filepath` — первое слово в `size`, **весь остаток строки** в `filepath`. Поэтому путь с пробелами не разорвётся.
- Но: `while` после `|` работает в **подоболочке**. Изменённый внутри `counter` после цикла снова будет старым.

> `find … | xargs du` ломается на именах с пробелами. Безопасно: `find … -print0 | xargs -0 du -h`.

## Время выполнения

```bash
START=$(date +%s.%N)
…
END=$(date +%s.%N)
echo "$END - $START" | bc
```

`%s` — секунды с 1970 года, `%N` — наносекунды. Bash умеет только целую арифметику, поэтому дробную разность считает `bc`. Проще: `time ./main.sh /var/log/` — замерит без правок скрипта.
