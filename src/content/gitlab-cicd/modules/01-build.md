## Утилита

```c
int main(int argc, char *argv[]) {
  if (argc != 2) {
    printf("Bad number of arguments!\n");
    return -1;
  }
  int num = atoi(argv[1]);
  switch (num) {
    case 1:
      printf("Learning to Linux\n");
      break;
    …
    case 6:
      printf("Learning to CI/CD\n");
      break;
    default:
      printf("Bad number!\n");
      return -2;
  }
  return 0;
}
```

Аргумент 1..6 — строка о теме, иначе ошибка. Задача утилиты — быть простым объектом для пайплайна: её собирают, проверяют стиль, тестируют и деплоят.

- `argc` — число аргументов **включая имя программы**: `./DO 1` → `argc = 2`.
- `argv[1]` — первый аргумент строкой.

## Код возврата: почему 255 и 254

Код возврата процесса в Linux — **одно число 0–255** (младший байт). Отрицательные значения переводятся по модулю 256:

| `return` в C | Код процесса (`$?`) |
|---|---|
| `0` | `0` — успех |
| `-1` | `255` |
| `-2` | `254` |

Поэтому тесты ждут 255 и 254. Проверено в Ubuntu 24.04 (WSL): `./DO` → 255, `./DO 7` → 254.

> Отрицательные коды из `main` — плохая практика: результат зависит от платформы (под Windows тот же бинарник дал другие коды). Принято `0` — успех, `1`, `2`… — ошибки, или `EXIT_SUCCESS` / `EXIT_FAILURE` из `stdlib.h`.

## Ловушка atoi

`atoi` преобразует **начало** строки и молча игнорирует остальное:

| Аргумент | `atoi` | Результат программы |
|---|---|---|
| `"1"` | 1 | Learning to Linux |
| `"1abc"` | 1 | **Learning to Linux**, код 0 |
| `"abc"` | 0 | Bad number!, 254 |
| `"99999999999"` | неопределённое поведение | — |

Проверено: `./DO 1abc` печатает «Learning to Linux» с кодом 0. Строгий разбор — `strtol` с проверкой, что вся строка — число:

```c
char *end;
errno = 0;
long num = strtol(argv[1], &end, 10);
if (errno != 0 || *end != '\0' || end == argv[1]) { /* не число */ }
```

## Makefile

```makefile
CC = gcc
CFLAGS ?= -Wall -Wextra -Werror -std=c11 -O2

.PHONY: all clean

all: DO

DO: main.c
	$(CC) $(CFLAGS) main.c -o DO

clean:
	rm -f *.o DO
```

| Элемент | Значение |
|---|---|
| `DO: main.c` | **цель** `DO` зависит от файла `main.c` |
| строка с отступом | **рецепт** — команда сборки. Отступ — **табуляция**, пробелы дадут `missing separator` |
| `all` | первая цель — выполняется по умолчанию при `make` |
| `.PHONY` | `all` и `clean` — не файлы; без этого файл с именем `clean` сломал бы цель |
| `CFLAGS ?=` | значение по умолчанию; можно переопределить: `make CFLAGS="-O0 -g"` |

make пересобирает цель, только если файл цели **старше** зависимостей:

```
$ make
gcc -Wall -Wextra -Werror -std=c11 -O2 main.c -o DO
$ make
make: Nothing to be done for 'all'.
```

> До исправления цель называлась `main` и не была связана с файлом `DO` — make не мог понять, что всё уже собрано, и пересобирал каждый раз.

## Флаги компилятора

| Флаг | Зачем |
|---|---|
| `-Wall -Wextra` | включить большинство предупреждений |
| `-Werror` | предупреждение = ошибка сборки: в CI код с предупреждениями не проходит |
| `-std=c11` | стандарт языка — одинаковое поведение на всех компиляторах |
| `-O2` | оптимизация |

## Артефакт

Результат сборки `app/DO` сохраняется в GitLab как **артефакт** — следующие стадии (test, deploy) берут готовый бинарник, а не собирают заново. Так тестируется и деплоится ровно то, что собрали (модуль 04).
