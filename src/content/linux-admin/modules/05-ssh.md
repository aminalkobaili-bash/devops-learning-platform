## systemd и службы

`systemd` — первый процесс системы (PID 1). Он запускает службы (units), следит за ними и перезапускает при падении. Описание службы — unit-файл, например `/lib/systemd/system/ssh.service`.

| Команда | Что делает |
|---|---|
| `systemctl status ssh` | состояние, PID, последние строки лога |
| `sudo systemctl start ssh` | запустить сейчас |
| `sudo systemctl stop ssh` | остановить сейчас |
| `sudo systemctl restart ssh` | перезапустить (рвёт текущие соединения службы) |
| `sudo systemctl reload ssh` | перечитать конфиг без остановки, если служба умеет |
| `sudo systemctl enable ssh` | запускать **при загрузке** |
| `sudo systemctl disable ssh` | не запускать при загрузке |
| `sudo systemctl enable --now ssh` | enable + start одной командой |
| `systemctl is-enabled ssh` | `enabled` / `disabled` |

> `start` и `enable` — разные вещи. `start` запускает до перезагрузки, `enable` — после каждой следующей загрузки. Служба может быть `active`, но `disabled` — после reboot она не поднимется.

В Ubuntu служба называется `ssh`, а процесс — `sshd` (SSH daemon).

## Конфигурация sshd

Файл сервера — `/etc/ssh/sshd_config` (не путать с `/etc/ssh/ssh_config` — это настройки **клиента**).

```diff
--- /etc/ssh/sshd_config
+++ /etc/ssh/sshd_config
-#Port 22
+Port 2022
```

Закомментированная строка показывает значение по умолчанию. Чтобы его изменить, строку раскомментируют и меняют.

### Зачем нестандартный порт

На порт 22 постоянно идут автоматические попытки подбора паролей. Перенос на 2022 сильно уменьшает шум в `auth.log`, но **это не защита**: сканер найдёт открытый порт за секунды. Реальная защита:

| Настройка | Эффект |
|---|---|
| `PasswordAuthentication no` | вход только по ключам |
| `PermitRootLogin no` | root не может войти по SSH |
| `AllowUsers amuser2` | белый список пользователей |
| fail2ban | блокирует IP после нескольких неудачных попыток |

### Безопасная смена конфига

```bash
sudo sshd -t                  # проверка синтаксиса: тишина = ОК
sudo systemctl restart ssh
```

> В Ubuntu 22.10 и новее (в том числе 24.04) sshd по умолчанию запускается через `ssh.socket`: порт слушает systemd. После смены `Port` нужно `sudo systemctl daemon-reload` и `sudo systemctl restart ssh.socket` — иначе sshd продолжит принимать подключения на 22. В Ubuntu 20.04 из проекта этого механизма нет.

> Не закрывай текущую SSH-сессию, пока не проверишь вход в **новой**: `ssh -p 2022 user@host`. Если конфиг сломан — текущая сессия останется, и можно будет исправить. Если порт закрыт фаерволом (`ufw`), сначала `sudo ufw allow 2022/tcp`.

## Проверка: что слушает порт

```bash
sudo ss -tlnp | grep 2022
```

| Флаг | Значение |
|---|---|
| `-t` | TCP |
| `-l` | только слушающие сокеты (LISTEN) |
| `-n` | числа вместо имён портов |
| `-p` | процесс, которому принадлежит сокет (нужен sudo) |

Результат из проекта (после reboot, через `netstat -tan`):

```
tcp   0.0.0.0:2022   0.0.0.0:*   LISTEN
tcp6  :::2022        :::*        LISTEN
```

- `0.0.0.0:2022` — слушает на всех IPv4-адресах.
- `:::2022` — на всех IPv6-адресах.
- То, что порт открыт **после reboot**, подтверждает `enable`.

`netstat` (пакет `net-tools`) устарел — его замена `ss` с теми же флагами.

## Процессы sshd

```bash
ps aux | grep sshd
```

Главный процесс `sshd` слушает порт; на каждое подключение он порождает дочерний процесс. Поэтому `restart` не обрывает уже открытые сессии — они живут в своих дочерних процессах.

## Подключение по ключу

```bash
ssh-keygen -t ed25519                         # на своей машине
ssh-copy-id -p 2022 amuser2@10.0.2.50         # публичный ключ → ~/.ssh/authorized_keys на сервере
ssh -p 2022 amuser2@10.0.2.50
```
