## cron

Служба, которая запускает команды по расписанию. У каждого пользователя своя таблица задач — **crontab**.

| Команда | Что делает |
|---|---|
| `crontab -e` | редактировать свою таблицу |
| `crontab -l` | показать |
| `crontab -r` | **удалить всю таблицу** без подтверждения |
| `crontab file` | заменить таблицу содержимым файла |
| `sudo crontab -u amuser -l` | таблица другого пользователя |

> `-r` и `-e` рядом на клавиатуре. `crontab -r` вместо `-e` молча стирает все задачи. Храни crontab в файле под git и загружай через `crontab file`.

## Формат строки

```
# m   h   dom mon dow   command
*/2   *   *   *   *     /usr/bin/uptime >> /home/amuser/cron_uptime.log 2>&1
```

| Поле | Значение | Диапазон |
|---|---|---|
| m | минута | 0–59 |
| h | час | 0–23 |
| dom | день месяца | 1–31 |
| mon | месяц | 1–12 |
| dow | день недели | 0–7 (0 и 7 — воскресенье) |

| Запись | Значение |
|---|---|
| `*` | любое значение |
| `*/2` | каждое второе: 0, 2, 4… |
| `1-5` | диапазон |
| `1,15` | список |

| Расписание | Строка |
|---|---|
| каждые 2 минуты | `*/2 * * * *` |
| каждый день в 03:30 | `30 3 * * *` |
| по будням в 9:00 | `0 9 * * 1-5` |
| 1-го числа каждого месяца в полночь | `0 0 1 * *` |
| при загрузке | `@reboot` |

Проверить расписание словами — crontab.guru.

## Окружение cron

cron запускает команды **не в твоей оболочке**:

- `PATH` урезан до `/usr/bin:/bin` — пиши **полные пути** к командам и скриптам;
- нет переменных из `~/.bashrc`;
- текущий каталог — домашний;
- оболочка — `/bin/sh`, а не bash.

## Куда девается вывод

```bash
command >> /home/amuser/cron_uptime.log 2>&1
```

| Часть | Значение |
|---|---|
| `>>` | дописать stdout в конец файла (`>` перезаписал бы) |
| `2>&1` | stderr туда же, куда stdout |

Без перенаправления cron пытается отправить вывод почтой; на сервере без почты он пропадает. **Без `2>&1` ошибки не попадут в лог** — их просто не будет видно.

## Найденная ошибка из проекта

Задача была записана так:

```
*/2 * * * * /user/bin/uptime …
```

В syslog каждые 2 минуты появлялись записи такого вида (PID условный):

```
CRON[1234]: (amuser) CMD (/user/bin/uptime …)
```

Выглядело так, будто всё работает. Но каталога `/user/bin` не существует (правильно — `/usr/bin`), команда падала с `not found`, и в лог ничего не попадало.

> **Запись `CMD` в syslog подтверждает только запуск, а не успешное выполнение.** Результат проверяют по самому артефакту: появился ли файл, есть ли в нём свежие строки.

Исправленный crontab — в `configs/cron/crontab`:

```
*/2 * * * * /usr/bin/uptime >> /home/amuser/cron_uptime.log 2>&1
```

## Проверка

```bash
crontab configs/cron/crontab
crontab -l
sleep 120 && cat ~/cron_uptime.log
grep CRON /var/log/syslog | tail
```

## Системные задачи

| Где | Формат |
|---|---|
| `/etc/crontab`, `/etc/cron.d/*` | с **дополнительным полем пользователя** после расписания: `0 3 * * * root /usr/local/bin/backup.sh` |
| `/etc/cron.daily/`, `cron.weekly/` … | просто исполняемые скрипты, запускаются раз в день/неделю |

Современная альтернатива — **systemd timers**: логи в `journalctl`, зависимости от других служб, пропущенный запуск догоняется (`Persistent=true`).
