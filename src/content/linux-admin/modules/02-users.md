## Пользователи и группы

Каждый процесс и файл принадлежит пользователю (UID) и группе (GID). Права на файл задаются для трёх категорий: владелец, группа, остальные.

| Файл | Что хранит |
|---|---|
| `/etc/passwd` | список пользователей, читается всеми |
| `/etc/shadow` | хеши паролей, читается только root |
| `/etc/group` | группы и их участники |

Строка `/etc/passwd` — 7 полей через `:`:

```
amuser2:x:1001:4:,,,:/home/amuser2:/bin/bash
```

(Числа UID и GID здесь для примера — свои смотри в `/etc/passwd`.)

| Поле | Значение |
|---|---|
| `amuser2` | логин |
| `x` | пароль хранится в `/etc/shadow` |
| `1001` | UID (обычные пользователи — с 1000) |
| `4` | GID основной группы (4 — `adm`) |
| `,,,` | комментарий (GECOS: полное имя, телефоны); adduser оставляет пустые поля через запятую |
| `/home/amuser2` | домашний каталог |
| `/bin/bash` | оболочка входа |

> UID 0 — root. Системные службы — UID 1–999, обычно с оболочкой `/usr/sbin/nologin`.

## adduser и useradd

| | `adduser` | `useradd` |
|---|---|---|
| Что это | интерактивный скрипт Debian/Ubuntu | низкоуровневая утилита, есть везде |
| Домашний каталог | создаёт | только с `-m` |
| Пароль | спрашивает | нужно отдельно `passwd` |
| Оболочка | `/bin/bash` | `/bin/sh` (без `-s`) |

```bash
sudo adduser --ingroup adm amuser2   # основная группа — adm
```

Группа `adm` в Ubuntu даёт право **читать логи** в `/var/log` без sudo.

## Добавить в группу: -aG

```bash
sudo usermod -aG sudo amuser2
groups amuser2      # adm sudo
```

| Флаги | Эффект |
|---|---|
| `-aG sudo` | **добавить** к текущим дополнительным группам |
| `-G sudo` | **заменить** все дополнительные группы на одну `sudo` |

> `usermod -G` без `-a` молча выкидывает пользователя из всех остальных дополнительных групп — частая ошибка.

Новая группа применяется к **новым** сессиям: пользователю нужно перелогиниться (или `newgrp sudo`).

## sudo

Выполнить команду от имени root, подтвердив **свой** пароль. Правила — в `/etc/sudoers` и `/etc/sudoers.d/`. В Ubuntu строка `%sudo ALL=(ALL:ALL) ALL` даёт группе `sudo` полные права.

```bash
sudo hostnamectl set-hostname user-2
```

- Редактировать правила только через `sudo visudo`: он проверяет синтаксис. Ошибка в `/etc/sudoers` = sudo перестаёт работать у всех.
- Все вызовы sudo пишутся в `/var/log/auth.log` — видно, кто и что выполнял (модуль 08).
- Вход под root по SSH в рабочих системах отключают; админы работают через личные учётки + sudo.

| Команда | Что делает |
|---|---|
| `id amuser2` | UID, GID, все группы |
| `groups` | группы текущего пользователя |
| `su - amuser2` | войти под другим пользователем (нужен **его** пароль) |
| `sudo -i` | интерактивная оболочка root |
| `sudo -l` | что мне разрешено через sudo |
