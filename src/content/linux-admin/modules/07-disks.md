## Три уровня взгляда на диск

| Уровень | Команда | Что отвечает |
|---|---|---|
| Устройства и разделы | `sudo fdisk -l`, `lsblk` | какие диски есть, как размечены |
| Файловые системы | `df -Th` | сколько места свободно на каждой смонтированной ФС |
| Каталоги и файлы | `du`, `ncdu` | **кто** занял место |

## fdisk -l

```bash
sudo fdisk -l /dev/sda
```

Результат из проекта: `/dev/sda` — 25 GiB, 52 428 800 секторов.

Проверка: 52 428 800 × 512 байт = 26 843 545 600 байт = 25 GiB.

- Сектор — минимальная адресуемая единица диска, обычно 512 байт.
- `GiB` (гибибайт) = 1024³ байт; `GB` (гигабайт) = 1000³. Поэтому «диск 25 GiB» = 26.8 GB.
- Без указания устройства `fdisk -l` покажет все диски, включая `/dev/mapper/…` тома LVM.

> `fdisk` без `-l` открывает интерактивный редактор разметки — ошибочная запись там уничтожит таблицу разделов.

## df -Th

```bash
df -Th
```

| Флаг | Значение |
|---|---|
| `-T` | показать тип ФС |
| `-h` | размеры в K/M/G |
| `-i` | вместо места — **inodes** |

Результат из проекта: `/` — ext4, 12G, занято 4.8G (45%).

Также в выводе будут `tmpfs` (ФС в оперативной памяти) и `/dev/loop*` (смонтированные snap-пакеты) — это не реальные диски.

### Inodes

Каждый файл занимает один inode (метаданные: права, владелец, где лежат блоки). Их число фиксируется при создании ext4. Миллионы мелких файлов (кеш, сессии) могут исчерпать inodes при свободном месте:

```bash
df -i
```

> Ошибка `No space left on device` при `df -h` = 60% — проверь `df -i`.

## du

```bash
sudo du -h --max-depth=1 /var | sort -h
sudo du -sh /var/log
```

| Флаг | Значение |
|---|---|
| `-h` | человекочитаемые размеры |
| `-s` | только итог по каталогу |
| `--max-depth=1` (`-d 1`) | разбивка на один уровень вглубь |

`sort -h` сортирует строки вида `92M`, `1.2G` по реальному размеру.

Результат из проекта: `/var` ≈ 919 MiB, из них `/var/lib` ≈ 700 MiB, `/var/log` ≈ 92 MiB, внутри него 89 MiB — `journal` (бинарные логи systemd).

## ncdu

Интерактивная версия `du`: стрелками по каталогам, сортировка по размеру, `d` — удалить.

```bash
sudo apt install ncdu
sudo ncdu /var
```

## Почему df и du могут не совпадать

Файл удалён (`rm`), но процесс всё ещё держит его открытым — например, служба пишет в лог, который удалили. `du` файл уже не видит, а место на ФС не освободится, пока процесс не закроет файл.

```bash
sudo lsof +L1      # открытые, но удалённые файлы
```

Решение — перезапустить процесс. Правильная очистка лога без перезапуска: `sudo truncate -s 0 file.log` вместо `rm`.

## Чистка места

```bash
sudo journalctl --disk-usage          # сколько занимает journal
sudo journalctl --vacuum-size=100M    # ужать до 100 MB
sudo apt clean                        # кеш скачанных .deb
sudo apt autoremove                   # ненужные зависимости и старые ядра
```
