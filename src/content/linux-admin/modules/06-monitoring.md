## top

Показывает процессы и нагрузку в реальном времени. Шапка — сводка по системе (время, uptime и проценты CPU в примере условные):

```
top - 12:00:00 up 10 min,  1 user,  load average: 0.00, 0.00, 0.00
Tasks: 104 total,   1 running, 103 sleeping,   0 stopped,   0 zombie
%Cpu(s):  0.0 us,  0.0 sy,  0.0 ni,100.0 id,  0.0 wa, ...
MiB Mem :   1971.0 total,  ...,   160.0 used, ...
MiB Swap:   2048.0 total, ...
```

Цифры из проекта: 104 процесса, load average `0.00 0.00 0.00`, RAM 160 из 1971 MiB, swap 2048 MiB.

### Load average

Три числа — средняя длина очереди на выполнение за **1, 5 и 15 минут**: процессы, которые работают или ждут CPU (в Linux — ещё и ждущие дискового ввода-вывода).

| Load (на 2 CPU) | Что значит |
|---|---|
| `0.5` | CPU в основном простаивают |
| `2.0` | оба ядра заняты полностью |
| `4.0` | на каждое ядро в среднем ещё один процесс ждёт очереди |

> Load сравнивают с **числом ядер** (`nproc`). Load 4 на 16 ядрах — спокойно, на 2 ядрах — перегрузка. Если 1-минутное число больше 15-минутного — нагрузка растёт.

### Строка CPU

| Поле | Время CPU на… |
|---|---|
| `us` | пользовательские процессы |
| `sy` | ядро |
| `id` | простой |
| `wa` | ожидание диска — высокий `wa` при низком `us` = узкое место в I/O |
| `st` | «украдено» гипервизором у VM |

### Память

`free` в Linux обычно мал — и это нормально: свободную память ядро использует под **кеш** файлов (`buff/cache`) и мгновенно отдаёт её приложениям при нужде. Смотреть надо на **`avail Mem`** — сколько реально доступно новым процессам.

```bash
free -h
```

Активное использование swap при нехватке `avail Mem` — признак, что RAM не хватает.

### Колонки процессов

| Колонка | Что это |
|---|---|
| `PID` | идентификатор процесса |
| `USER` | владелец |
| `RES` | физическая память процесса |
| `VIRT` | виртуальная память (включая не загруженное) — обычно сильно больше RES |
| `%CPU`, `%MEM` | доля CPU и RAM |
| `S` | состояние: `R` — работает, `S` — спит, `D` — ждёт I/O, `Z` — зомби |

### Горячие клавиши top

| Клавиша | Действие |
|---|---|
| `M` | сортировать по памяти |
| `P` | сортировать по CPU |
| `1` | показать каждое ядро отдельно |
| `k` | послать сигнал процессу (убить) |
| `q` | выход |

В проекте: больше всех памяти — PID 692 `snapd`, больше всех CPU — PID 567 `multipathd`.

## htop

Удобнее `top`: цветные шкалы, прокрутка, мышь.

| Клавиша | Действие |
|---|---|
| `F6` | выбрать колонку сортировки |
| `F4` | фильтр по имени (в проекте — `sshd`) |
| `F5` | дерево процессов (родитель → потомки) |
| `F2` | настройка: добавить meters (hostname, clock, uptime) |
| `F9` | послать сигнал |

## Неинтерактивные команды

Для скриптов и быстрых проверок:

```bash
uptime                          # время работы и load average
nproc                           # число ядер
free -h                         # память
ps aux --sort=-%mem | head -5   # топ-4 по памяти
ps aux --sort=-%cpu | head -5   # топ-4 по CPU
```

## Сигналы

| Сигнал | Номер | Что делает |
|---|---|---|
| `SIGTERM` | 15 | вежливо попросить завершиться (по умолчанию у `kill`) |
| `SIGKILL` | 9 | убить немедленно, процесс не может перехватить |
| `SIGHUP` | 1 | многие демоны перечитывают конфиг |

```bash
kill 1234        # SIGTERM
kill -9 1234     # SIGKILL — только если TERM не помог
```

> `kill -9` не даёт процессу закрыть файлы и соединения. Сначала всегда `SIGTERM`.
