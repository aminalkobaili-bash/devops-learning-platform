## Задача

Граф из 4 городов, рёбра в обе стороны с одинаковой стоимостью. Найти самый дешёвый (и самый дорогой) маршрут, который выходит из `a`, проходит каждый город **ровно один раз** и возвращается в `a`. Это задача коммивояжёра (TSP) — решаем полным перебором чистым SQL.

| | a | b | c | d |
|---|---|---|---|---|
| **a** | — | 10 | 15 | 20 |
| **b** | 10 | — | 35 | 25 |
| **c** | 15 | 35 | — | 30 |
| **d** | 20 | 25 | 30 | — |

## Граф как таблица рёбер

```sql
CREATE TABLE routes (
  point1 VARCHAR(1),
  point2 VARCHAR(1),
  cost INTEGER,
  PRIMARY KEY (point1, point2),
  CHECK (point1 <> point2)
);
```

- **Составной `PRIMARY KEY`** — уникальна пара `(point1, point2)`: между двумя городами одно ребро в каждую сторону.
- **`CHECK (point1 <> point2)`** — запрет петли «город сам в себя».
- Неориентированный граф хранится двумя строками: `('a','b',10)` и `('b','a',10)`. Так JOIN по `point1` находит соседей в обе стороны без `OR`.

## WITH RECURSIVE

```sql
WITH RECURSIVE cte AS (
  -- 1. якорь: стартовые строки
  SELECT …
  UNION ALL
  -- 2. рекурсивная часть: ссылается на cte
  SELECT … FROM cte JOIN … WHERE …
)
SELECT * FROM cte;
```

Как выполняется:

1. Якорь выполняется **один раз** → это первая «рабочая таблица».
2. Рекурсивная часть выполняется над **строками последней итерации** (не над всем накопленным результатом).
3. Новые строки добавляются в результат и становятся рабочей таблицей для следующего шага.
4. Как только рекурсивная часть вернула **0 строк** — остановка.

> Нет условия, которое рано или поздно обнулит рекурсивную часть, — запрос уйдёт в бесконечный цикл. Здесь его обнуляет запрет повторных вершин: после 4 городов идти некуда.

- Типы колонок якоря и рекурсивной части **должны совпадать**. Поэтому в якоре `point1::text`: массив строится как `text[]`, и рекурсивная часть дописывает в него тоже `text`.
- `UNION ALL` обычно; `UNION` дополнительно убирает дубликаты строк между итерациями.

## Массивы PostgreSQL

| Выражение | Результат |
|---|---|
| `ARRAY['a', 'b']` | создать массив |
| `tour \|\| 'c'` | добавить элемент в конец → `{a,b,c}` |
| `'c' <> ALL(tour)` | `true`, если `c` не равен **ни одному** элементу |
| `'c' = ANY(tour)` | `true`, если `c` равен **хотя бы одному** элементу |
| `array_length(tour, 1)` | длина по первому измерению |

`r.point2 <> ALL(p.tour)` — главное условие решения: не идти в город, который уже есть в маршруте.

## Как растут пути из a

| Итерация | Длина `tour` | Пример | Путей |
|---|---|---|---|
| якорь | 2 | `{a,b}` | 3 |
| 1 | 3 | `{a,b,c}` | 6 |
| 2 | 4 | `{a,b,c,d}` | 6 |
| 3 | — | все соседи `d` уже в маршруте | 0 → стоп |

Из `{a,b,c,d}` осталось только вернуться в `a` — это делает отдельный CTE `final_paths`: берёт пути длины 4 и добавляет ребро в `a`.

## Несколько CTE подряд

```sql
WITH RECURSIVE paths AS (…),
final_paths AS (…)
SELECT …
```

`RECURSIVE` пишется один раз после `WITH` и относится ко всему блоку. Следующий CTE (`final_paths`) читает предыдущий (`paths`).

## Отбор минимума и максимума

```sql
SELECT total_cost, tour FROM final_paths
WHERE total_cost = (SELECT MIN(total_cost) FROM final_paths)
```

Не `ORDER BY … LIMIT 1`: маршрутов с минимальной стоимостью может быть несколько. Здесь их два — `a→b→d→c→a` и обратный ему `a→c→d→b→a`, оба по 80. Максимум — 95.

## Ограничения подхода

- Полный перебор: из `a` через `n − 1` остальных городов — `(n − 1)!` маршрутов. 4 города → 6, 10 городов → 362 880, 15 → ~87 млрд. Для больших графов SQL-перебор не годится.
- `array_length(p.tour, 1) = 4` привязывает запрос к числу городов. Обобщение: `= (SELECT COUNT(DISTINCT point1) FROM routes)`.
- В PostgreSQL 14+ есть встроенная защита от циклов: `CYCLE point2 SET is_cycle USING path` после CTE.
